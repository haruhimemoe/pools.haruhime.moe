# AGENTS.md

Rules for any agent (or human) working in this repo. Authoritative; `CLAUDE.md` only layers on top.

## 1. What this is

pools.haruhime.moe: past osu! tournament mappools in their own `pools` database, an importer that fills it from otdb's export and keeps a plain pack per pool on packs.haruhime.moe, and a read-only public site (pool and map search, map history, a compliance check) with an admin area. What users read lives in `README.md`, `/data`, `/submit`, `/credits` and `content/legal/`; section 7 says what has to stay in step with the code.

**Hard rule: we never host files.** No `.osz`, audio, image or video bytes pass through or are stored by our code. "Open in packs" and the mirror link send people elsewhere.

## 2. Layout

```
src/app/          routes only (thin; compose components)
src/components/   feature folders (admin/, auth/, check/, home/, layout/, maps/, pools/, search/); primitives come from @haruhimemoe/ui
src/hooks/        client hooks (search results, the check)
src/constants/    static data (site, pools, db names, search, api limits, compliance, legal)
src/utils/        pure, stateless helpers grouped by domain
src/lib/          integration plumbing (db, auth, osu!, mirror, packs client, rate limits, the import runner)
src/services/     database work
src/models/       Mongoose schemas and indexes; typed driver collections
src/schemas/      zod schemas and shared types
content/legal/    MDX legal pages
scripts/          admin runners for `bun run` (thin: the work lives in src/lib and src/services)
public/brand/     logos, icon and palette generated by @haruhimemoe/brand (never edited by hand)
tests/            unit/ (node), components/ (jsdom), integration/ (node + in-memory Mongo), fixtures/, helpers/, setup/
llms.txt          the repo's own llms.txt; the site's is built by src/utils/llms-txt.ts
```

## 3. Code style

- TypeScript 7, `strict`, `noUncheckedIndexedAccess`. No `any`; validate external data with zod.
- Biome is the only linter and formatter (`bun run check`, `bun run check:fix`).
- No barrel files in `src/`. Import exact local paths. npm packages are imported from their published entry points.
- One component per file, PascalCase filename, Tailwind only. Components are presentational; data lives in services and hooks.
- `utils/` is pure. Server-only modules `import "server-only"`. `src/utils/pack-input.ts`, `fingerprint.ts` and `source-pools.ts` use node:crypto: never import them from client code. Client code never imports the `@haruhimemoe/osu` root (it holds the osu! secret) or `@haruhimemoe/compliance` (its data stays on the server); `tests/unit/tooling/client-imports.test.ts` enforces both.

## 4. File headers

Every `.ts`, `.tsx`, `.mjs`, and `.css` source file starts with:

```ts
/**
 * @file <repo-relative path>
 * @desc <what it is and why>
 * @author David @dvhsh (https://dvh.sh)
 * @created Ddd MMM D, YYYY
 * @modified Ddd MMM D, YYYY
 */
```

Dates match `date "+%a %b %-d, %Y"`. Update `@modified` on edits, never `@created`. Exported functions get a JSDoc block with `@function`, `@param`, `@returns` (and `@throws` when they throw).

## 5. Tests

- Everything under `tests/`, mirroring `src/` paths. Write the failing test first.
- `bun run test` runs all three Vitest projects. The unit project runs with `TZ=America/Los_Angeles` on purpose.
- Tests never reach osu!, the mirror, otdb or packs: msw (`tests/helpers/msw.ts`, `onUnhandledRequest: "error"`) with `tests/helpers/{osu,hinai,packs}-server.ts`, or injected fakes.
- Integration tests use `setupTestDb()` and build rows with `makePool` / `makeMap` (`tests/helpers/records.ts`); admin sessions come from `createTestAdmin()`.
- `tests/integration/e2e/otdb-import.test.ts` runs the importer over the real otdb export only when `POOLS_E2E_EXPORT` names the file; it's skipped otherwise.
- Coverage floor: 90% on `src/utils/**` and `src/schemas/**`.

## 6. Visual system

osu!-web look from `@haruhimemoe/ui`: `src/app/globals.css` imports its theme and pins `--hue: 200` (pools' hue) and `--h2-l: 42%` (4.5:1 for white on h2 at that hue). Dark only. Font: Nunito. Page titles go through `PageHeader`; tables sit in an `overflow-x-auto` wrapper so phones scroll them. Every star rating says it's without mods.

`NEXT_PUBLIC_POOLS_BETA=true` (read by `isBeta()` in `src/lib/beta.ts`, written into the build by Next.js) shows a "beta" pill beside the header wordmark on every page. The pill sits outside the wordmark link, so the link's accessible name stays "pools" (the wordmark's dot is `aria-hidden`). It changes nothing else: no robots or `noindex`, no title template change.

## 7. Legal copy and docs

- Legal pages are `content/legal/*.mdx`, registered in `src/constants/legal.ts`; bump `lastUpdated` with any wording change. `tests/unit/content/legal-content.test.ts` guards the clauses.
- Every source kind (`SOURCE_KINDS`: otdb, host, community) is credited on each of its pools' pages (`PoolSources`) and on `/credits` (`SOURCE_CREDITS` in `src/constants/pools.ts`), and `/data` says where pools come from; a new kind gets all three. The footer credits no source: pools come from otdb, tournament hosts and community members, so copy never names otdb as the only source (`tests/unit/content/copy-rules.test.ts`).
- A new per-IP counter goes in `privacy.mdx`. Every request our server makes to a third party is listed in `disclaimer.mdx` ("How our requests identify themselves").
- A change people see updates the README's Features and, when it touches a page, `src/utils/llms-txt.ts`.
- No em dashes in any copy (`tests/unit/content/copy-rules.test.ts`). osu! wiki text is CC BY-NC: paraphrase, never copy.

## 9. Pool data

- The database is always `pools` (`DB_NAME` in `src/lib/db.ts`). `connectDb()` reads the user's privileges (`connectionStatus` with `showPrivileges`) and refuses to go on when they reach any other database (`checkDatabasePrivileges` in `src/lib/db-privileges.ts`). It fails closed: an answer that doesn't say who is signed in, or a signed-in user with no privileges listed, is refused too. better-auth and every service go through `connectDb()` first.
- `POOLS_ALLOW_SHARED_DB_USER=true` (exactly `true`, trimmed; anything else is strict) allows a user that reaches other databases, like one shared with packs: the check still refuses the answers above and a user without find, insert, update, remove and createIndex on all of `pools`, and logs one `console.warn` naming the other databases (never the URI). Strict is the default; `.env.example` leaves it empty and a test keeps it that way. SECURITY.md states the risk.
- Server env comes from `src/env.ts` only. `ADMIN_OSU_IDS`, `PACKS_URL`, `POOLS_SERVICE_TOKEN` and `POOLS_ALLOW_SHARED_DB_USER` are read on every call by their own getters. Never print a secret; never read `.env.local` in a tool call.
- Pool ids are `<source>-<id>` for a source pool's first version and `-2`, `-3` for later ones, never reused (`nextPoolId`). An id is also packs' ref for the pool's pack.
- Sources (`src/schemas/pool.ts`, a zod discriminated union on `kind`): otdb keeps its v1 shape `{ kind, id, url, importedAt }`; host and community are `{ kind, id, credit: { name, url? }, importedAt }`, the name 1 to 100 characters once trimmed and through the content filter, the link https only. Leave `credit.url` out when there is none: the driver stores `undefined` as `null`, which fails the schema and drops the pool from every page. `formerSources` entries add `leftAt`. Host and community ids come from `src/utils/source-ids.ts` (a letter, then 7 base36 characters, so they sort after otdb's numeric ids in `bySourceId` and never take a merged record's name). Credit links render with `rel="nofollow ugc noopener"`.
- `tournament`, `round` and `year` hold the effective values: an admin's `edited` value wins, else what `namePartsOf(name)` reads. `tournamentKey`, `searchText` and `sortName` are recomputed with them (`derivedFields`). `visible` is `!hidden && supersededBy === null`, and every public index starts with it.
- The importer (`src/utils/import-plan.ts`) tracks changes per source: a changed source leaves its record (into `formerSources`), a record with no source left is superseded, a new record inherits `hidden`, `badged` and `edited`, a returning fingerprint revives its record. A record takes its name, notes and slots from its lowest source id only when that source is in the run; while it's skipped or missing, the record keeps what it has. The report's superseded and revived lists are net: a record superseded and revived in one run is neither. It never changes `hidden`, `badged` or `edited` on a stored record. Rerunning is safe.
- Maps carry `usage` (`count`, `lastYear`, `playedAs`, `shown`), rebuilt by `src/services/usage.ts` after every import and every admin change to hidden or year. `count` is distinct current pools; `shown` decides whether `/maps/[id]` exists.
- Hidden pools are invisible on every public surface (search and `/check` within 5 minutes: the CDN keeps their answers that long and nothing can purge them); public pages never read cookies, so `/pools/[id]` 404s them and admins preview at `/admin/pools/[id]`. Superseded pools keep their page with "Replaced by", and are out of search, history, usage, counts, the sitemap and llms.txt; their pack goes unlisted.
- Pack sync: `src/utils/pack-input.ts` builds the pack input and its hash, `src/utils/sync.ts` decides which pools are due (never `gone`; `error` always; `rejected` only when the input changed or on request), `src/lib/packs-client.ts` sorts packs' answers, `src/services/sync.ts` sends at most 5 at a time. 401 and 503 `not_configured` stop a run.
- `bun run import` reads `IMPORT_SOURCES` (otdb) only; host and community pools come in through the admin page. `bun run import otdb [--dry-run] [--file <path>] [--no-sync] [--resync rejected]` (`scripts/import.ts` then `src/lib/import-runner.ts`) runs with the `react-server` condition and writes to the database `MONGODB_URI` names (Bun loads `.env.local`). A real run stores one report in `imports`, even when it throws partway (`ok: false`, with the error). It can't revalidate the site: after an import, Refresh public pages on `/admin` (`POST /api/admin/revalidate`) rebuilds the home page, sitemap, llms.txt and every pool and map page. Agents run it only with `--dry-run` unless they're asked to import.
- The home page, sitemap and llms.txt reads (`loadHomeCounts`, `listCurrentPools`, `listListedMaps`) come back empty only under `SKIP_ENV_VALIDATION`. At runtime a database error throws, so ISR keeps the last good version instead of storing an empty one.

## 10. Search, the check and admins

- `/search` is a static page; results come from `GET /api/search` (CDN cached 5 minutes and never served stale, so a hidden pool leaves search within 5 minutes; 60 requests a minute per IP). Queries are built in `src/utils/search-query.ts`: every one hints the index behind its sort, runs under `maxTimeMS`, matches text as escaped substrings, pages 50 at a time (page at most 200, query at most 100 characters). A new sort needs its index in `src/models` and an explain case in `tests/integration/services/search.test.ts`. No public request runs an aggregation pipeline: public counts use `countMatching` (`src/services/count.ts`, the `count` command), because the driver's `countDocuments` is an aggregation. Admin pages may use `countDocuments`.
- `/api/check` asks osu! only through `budgetGate` (50 calls a minute across instances, 20 per IP) and caches beatmapset facts in `setFacts` for 24 hours. A complete answer stays 5 minutes on the CDN, since its map labels and usage come from pools; a partial answer, or one whose maps lookup failed, is never cached.
- Only osu! ids in `ADMIN_OSU_IDS` can sign in: the user hook refuses anyone else, the session hook checks again, and `getAdminFromHeaders` reads a removed id as signed out. Admin routes answer 404 to everyone else, then refuse other origins (`refuseCrossSite`), then parse a JSON body.
